# 全仓库装修计划

## 目标

把 Pass Vault V2 从“功能已经堆叠完成的安全项目”整理成一个可长期维护、可公开使用、可持续发布的产品仓库：代码边界清晰、前端视觉统一、双运行时契约明确、文档可导航、测试和发布门禁可信。

## 已确认现状

- 一个仓库、同一套 `public/` 前端源码，分别打包为 Cloudflare Worker/D1/R2 与 Linux Node/SQLite/本地附件两个独立部署目标。
- 当前 `main` 已包含 v1.1.71，会话代际安全修复和文档更新已完成。
- 现有全量测试为 331/331，项目包含大量端到端 UI、双后端、加密、Passkey、附件和发布测试。
- 根目录存在大量被 `.gitignore` 忽略的测试 SQLite 临时文件，属于工作区卫生问题；不得误删生产数据。
- `artifacts/` 为本地证据目录且被忽略；公开仓库不应依赖它作为文档或构建输入。
- 目前没有 `.github/` 工作流目录，缺少公开 CI、Issue/PR 模板和仓库级贡献入口。

## 依赖顺序

```text
审计与边界冻结
  ├── 仓库清理/工程入口/CI
  ├── 共享契约与双端 API 文档
  └── 前端视觉与交互系统
          └── 功能 UI 分批重构
                  └── 双端发布、生产烟测、公开 Release
```

## 实施批次

### Phase 0：基线与卫生

- [ ] 删除确认无用的本地 `.tmp-clean-*.sqlite` 和其他测试残留；保留生产备份目录不动。
- [ ] 检查并补强 `.gitignore`、Node 版本说明、环境变量示例和本地开发入口。
- [ ] 建立 `.github/workflows/ci.yml`、Issue 模板、PR 模板和 CODEOWNERS（若仓库权限允许）。
- [ ] 保持当前全量测试绿灯，并记录基线。

### Phase 1：仓库结构与公开入口

- [ ] 把 README 变成产品首页：产品定位、截图/演示、架构边界、快速开始、部署入口、路线图和安全报告。
- [ ] 统一中英文文档导航，清理重复/过期 release notes 的公开噪音；保留发布审计所需历史记录。
- [ ] 把 `docs/` 分成 architecture、development、operations、security、api 四个可查找区域；所有双端差异单独说明。
- [ ] 增加 `docs/DECISIONS.md` 或 ADR 索引，记录零知识边界、双后端、附件一致性和 Passkey 边界。

### Phase 2：工程与契约

- [ ] 把重复的双后端校验规则、错误码、密文 envelope、附件 metadata 契约集中到共享模块，避免文档/代码漂移。
- [ ] 为 API client、crypto boundary、session generation、attachment lifecycle 建立清晰模块边界。
- [ ] 加入格式化/静态检查的明确入口；不引入不必要依赖。
- [ ] 将发布脚本改成可审计、可重复、明确区分 Linux/Cloudflare 的流程。

### Phase 3：产品界面装修

- [ ] 先建立 design tokens：颜色语义、表面层级、间距、圆角、阴影、焦点环、动效、深色模式。
- [ ] 重做锁定/登录/注册/安全中心为统一的移动优先入口。
- [ ] 重做主壳层：导航、搜索、分类、分组、批量工具栏、空状态和错误状态。
- [ ] 重做五类资料卡片/详情/编辑器；保持密码显隐、TOTP、附件、Passkey 和回收站安全行为不变。
- [ ] 逐页覆盖 Chromium/WebKit，320px/390px/桌面，减少闪烁、溢出和焦点丢失。

### Phase 4：安全、性能与可观测性

- [ ] 对登录、会话、Passkey、备份导入、附件上传/删除、批量写入做威胁模型复查。
- [ ] 实测首屏、解锁、列表、搜索、附件预览和 3–4 秒取件目标；只保留有数据证明的优化。
- [ ] 统一客户端错误状态和服务端日志字段；不记录明文、vault key、真实账户或生产标识。
- [ ] 增加依赖、秘密、制品和文档脱敏门禁。

### Phase 5：发布

- [ ] 独立审查最终 diff。
- [ ] 全量测试、lint、typecheck、build、package-release、SHA256、敏感信息扫描。
- [ ] 从最终 commit 创建新 annotated tag，不移动旧 tag。
- [ ] 双端备份、部署、Chromium/WebKit 生产烟测、清理临时账户。
- [ ] 更新中英文 Release、资产、仓库元数据并匿名回下载验证。

## 验收标准

- 公开仓库首页 30 秒内能说明产品是什么、两种部署有什么区别、如何开始。
- 任何功能契约只在一个权威代码位置定义，双端行为一致且差异显式。
- 移动端最小 320px 无横向溢出，主要触控目标不少于 44px；锁库/切换账户后无迟到敏感写入。
- `npm test`、`npm run lint`、`npm run lint:docs`、`npm run typecheck`、`npm run build`、制品测试全部真实通过。
- GitHub Actions 能从干净环境安装、构建并运行安全的非生产测试门禁。
- 公开文件不包含真实生产域名、账户、资源 ID、邀请值、令牌或密钥。

## 风险与控制

| 风险 | 控制 |
|---|---|
| 全仓库改动过大导致安全回归 | 按垂直切片，每批独立测试、独立提交和审查 |
| UI 装修改变安全行为 | 先锁定行为测试，再只改结构/样式，逐项补视觉测试 |
| 双端契约漂移 | shared contract + 双后端 contract tests + API 文档同步 |
| 清理误删数据 | 只删除仓库根目录明确命名的测试临时文件；生产数据路径先核对 |
| 依赖升级引入新风险 | 单依赖变更、npm audit、lockfile 审查、全量测试 |
