# PassVault Cloudflare：资料版本历史与安全分享

## 范围

仅实现、测试和部署 Cloudflare Worker/D1 版本；不修改或发布 Linux 版本。

## 资料版本历史

- 适用于 `account`、`website`、`note`、`totp`、`custom`，首版不含二进制附件。
- 当前资料每次成功 CAS 覆盖时，由 D1 `BEFORE UPDATE` 触发器在同一条事务内归档旧的密文 envelope；服务端从不解密历史。
- 服务端可看到归属用户、opaque 资料 ID、类型、revision、密文大小与服务端时间；看不到标题、密码、TOTP、自定义字段值或其他明文。
- 每条资料最多 10 个版本，全库最多 50 个版本；裁剪发生在原子更新事务中。CAS 失败不产生历史。
- 用户查看历史时，浏览器用现有 vault key 解密旧 envelope；恢复旧版本是一次新的 CAS 覆盖，因此恢复前的当前版本也会自动归档。
- 永久删除资料依赖外键级联同步删除历史；软删除/恢复、收藏、置顶、移动分组等密文覆盖同样形成版本。
- 历史不纳入普通备份恢复：恢复备份不会复活过去已经裁剪或删除的历史，避免隐藏生命周期能力随备份意外扩散。
- 锁定、退出、后台隐私遮罩时清空历史明文状态、目标引用和对应 DOM。

## 安全分享

- 首版适用于单条非附件资料；不分享二进制附件，也不实时同步后续修改。
- 浏览器生成随机 256-bit 分享密钥，用 AES-GCM 加密一份独立快照。
- 服务端只保存密文、IV、随机分享 token 的 SHA-256、到期时间、最大查看次数、已查看次数，以及由 vault key 加密的所有者备注；不保存分享密钥或资料明文。
- 安全边界说明：分享机制使用独立客户端密钥；现有 Passkey 辅助解锁会将 vault key 交由服务端 KEK 包装，因此不得把整个产品笼统宣传为“服务端绝不可能恢复 vault key”。普通主密码路径与分享密钥仍保持客户端边界。
- 分享加密使用用途隔离 AAD：`pass-vault-v2:share:1:<token>`。
- 分享 URL 形如 `/share#<token>.<key>`；token 与 key 均只存在于 URL fragment，浏览器显式 POST token 的服务端哈希进行消费，fragment 不会随页面请求发送。
- 到期选项：1 小时、1 天、7 天；最大查看次数：1、3、10。服务端硬限制最长 7 天、最多 10 次、单用户最多 20 个活跃分享、密文不超过 512 KiB。
- 匿名读取使用单条原子 D1 `UPDATE ... RETURNING` 消费查看次数；并发请求不能超过限制。过期、撤销、耗尽统一返回不可用，不泄露状态细节。
- 所有者可列出自己的分享、查看已用/上限和到期时间，并随时撤销；列表中的资料名称只来自 vault-key 加密的备注。
- 定时任务清理已过期或已撤销超过 24 小时的密文；撤销立即使匿名读取失败。
- 匿名分享页不读取保险库会话资料，不写 URL query、遥测或 DOM 属性中的明文/密钥；首次解析后立即清除 fragment，切后台清空内容。

## 安全与兼容门禁

- 严格验证 JSON exact keys、token/key 长度、时间边界、密文大小和整数限制。
- 所有已认证写操作保持 Origin + CSRF；分享所有权由会话用户 ID强制约束。
- 版本历史归档与资料更新为同一 D1 事务；CAS 失败不留幽灵历史，更新成功不会缺历史。
- 分享创建、匿名读取、撤销、过期、并发计数、账户隔离、密钥不出 fragment、锁定清理均需 RED→GREEN 测试。
- Chromium 与 WebKit 覆盖桌面和 390px 手机视口；发布前运行 Cloudflare 专项 typecheck、build、Wrangler dry-run、迁移演练、独立安全审查和生产烟测。
